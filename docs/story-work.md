# 허들링 앱 화면 설계 — 기존 작업 프로세스 (AI 없이 손으로 했던 방식)

> `docs/story-service.md`(무엇을 위한 일인지)와는 별개로, 실제로 어떻게 작업했는지를 기록한 문서입니다.

## 프로세스 7단계

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다.
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다.
6. 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다.

## 산출물 / 게이트 / 에이전트 경계

| # | 단계 | 명사(산출물) | 게이트(멈칫 지점) | 에이전트 경계(넘어가는 지점) |
|---|---|---|---|---|
| 1 | uibowl 레퍼런스 수집 | 경쟁사 레퍼런스 수집 목록 | 없음 | 없음 |
| 2 | 레퍼런스 분석 → 반영 부분 도출 | 분석 결과(반영 포인트 목록) | **있음** — 3번(화면설계)로 넘어가기 전 게이트 | 없음 |
| 3 | 화면설계 문서 구체화 | 화면설계 문서 | (게이트는 2→3 전환에 속함, 3 자체는 아님) | 없음 |
| 4 | figma UI 키스크린 그리기 (390×844, 2~3개) | UI 키스크린 | **있음** — 멈칫/컨펌 필요 | Figma(도구) |
| 5 | 내부 관계자 협의 → 컨셉 시안 확정 | 컨셉 시안(확정본) | **있음** — 멈칫/컨펌 필요 | 내부 관계자(사람) — 의견 수렴 후 결정권 복귀 |
| 6 | 디자인 토큰/컴포넌트 제작 + 화면 디자인 | 디자인 토큰, 컴포넌트, 화면 디자인 | 4·5번 게이트 통과가 6번 진입 조건 (별도 게이트 없음) | 없음 |
